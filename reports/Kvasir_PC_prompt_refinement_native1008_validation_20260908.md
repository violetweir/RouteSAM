# Kvasir：对应图生成框提示，SAM3 重解码实验

日期：2026-09-08。100 张原 validation，保持原 800/100/100 划分及 8/792 标注身份，无学生。

结论：前景—背景对应图转换成单个框、再交给 SAM3 几何解码的本轮方案失败。直接结果明显下降，固定回退规则也未超过 TP。没有运行 test，原 TP 独立 Router 基线保持。

## 配置核对与预实验修正

历史“256 传播”中的 256 是传入与输出的图像画布尺寸；SAM3 video 模型内部仍使用 1008。代码依据为 `sam3/model_builder.py` 和 `sam3/model/sam3_video_inference.py` 中的 `image_size=1008`，原传播评估脚本只缩放输入帧，没有把内部编码改为 256。

最初的 CPU 预实验将 SAM3 image processor 的内部尺寸设为 256，与历史推理配置不一致；其全部结果保存在 `work/kvasir_pc_prompt_refine_20260908`，不能据此判断主实验是否有效。随后按内部 1008 重跑全部 100 张 validation。本报告主表只使用补跑结果。

正式补跑：相同 SAM3-base checkpoint，内部 1008、输入输出画布 256，GPU bfloat16 autocast，单图推理；不使用 CPU 兼容替换。图像是对 TP 所选目标帧重新进行几何提示解码，与原视频传播的最终输出仍属于不同推理步骤，因此另设 TP 框重解码对照。

TP 与对应图所用的支持 anchor 来自历史五折 OOF TP 选择；原 anchor、路径与默认 mask 固定。对应图沿用上一轮从 256 图像提取的 18×18 CPU float32 token，其分辨率刻意与 KNN 特征协议一致，不应与最终 SAM3 解码的内部 1008 混淆。

## 提示构造与对照

1. TP-box 对照：直接使用 TP 默认 mask 的包围框。
2. Prototype-box：使用前景 prototype 与 target patch 的余弦图生成框。
3. FG/BG-box：使用 anchor 前景 top-min(3,前景patch数) 的平均余弦减背景 top-3 平均余弦，生成框。

两种对应框使用同一固定规则：把 TP mask 缩成 18×18 面积权重；权重>0.25 的区域膨胀两格作为 ROI；K 取 TP 预测的网格面积；取 ROI 内最高 K 个对应位置，选择与 TP 重叠质量最大的连通分量，取包围框并向外加一格。

所有框均为归一化 cx/cy/w/h，先完成构造和推理再加载 GT。三组通过相同 SAM3 image 几何接口解码，仅使用接口内部的 `visual` 占位，不加入 polyp 文本。每组选择模型置信度最高的 query；空输出回退 TP。

同时报告一个事先固定的回退规则：只有修正 mask 与 TP 的 Dice≥0.9、面积比在[0.5,2]、模型分数≥0.5，才采用修正结果，否则返回原 TP。该规则仅约束变化幅度，不保证修正正确。

主要验收对象为 FG/BG-box 的回退后结果；它需分别优于原 TP 和同规则的 TP-box 对照：平均提升≥0.003、95% 配对 bootstrap 区间下界>0、至少3/5原OOF折改善。不能事后按最好消融替换主要对象。

## Validation 结果

| 方法 | 直接使用新 mask 的 Dice | 按固定规则回退后的 Dice |
|---|---:|---:|
| 原 TP 独立 Router | **0.851755** | **0.851755** |
| TP 框直接重解码 | 0.846762 | 0.848227 |
| 原型对应框重解码 | 0.500498 | 0.847727 |
| 前景—背景对应框重解码 | 0.553532 | 0.848991 |

FG/BG 回退后相对 TP：-0.002765，95% 区间[-0.006003,0.000091]；3张改善、90张持平、7张下降。只采用10张修正结果，仍未产生净收益。

FG/BG 回退后相对 TP-box 回退后：+0.000764，95% 区间[-0.003519,0.004859]，同样未通过标准。

TP-box 回退采用94张，Prototype-box采用12张，FG/BG-box采用10张。必须同时查看直接输出和回退后输出：接近原基线主要可能来自大量回退，不能误写为新分支本身表现接近 TP。

## 提示质量诊断

以下仅是 GT 事后诊断，不参与提示或选择。

| 提示 | 平均 GT 覆盖率 | 框占图像面积 | 框内 GT 占比 |
|---|---:|---:|---:|
| TP 框 | 0.910412 | 0.183685 | 0.737343 |
| 原型对应框 | 0.876002 | 0.316653 | 0.402626 |
| 前景—背景对应框 | 0.919422 | 0.329686 | 0.387387 |

FG/BG 框的平均面积约为 TP 框的1.79倍，覆盖率只增加约0.009，框内病灶比例大幅降低。此前对应图较高的 patch AUC 不保证转换为单个大框后仍能精确指向病灶；合并成框会丢失框内部的前景/背景分布。

样例图中，较大的对应框有时让输出转向背景或产生碎片。这里采用按 GT Dice 差选取的最差、中位、最佳三个例子，仅供失败诊断，不代表样本平均分布。样例保存在 `examples.png`。

这些结果支持排除本轮“Top-K连通分量→扩框”的具体规则，尚不能证明所有对应提示都无效，也不能单独区分框扩张、query选择、缺少原传播记忆等因素的贡献。

## 后续方向

暂不接入任何新修正分支。若继续，应比较能保留局部前景/背景信息的提示方式，例如在 TP 默认结果支持下构造少量正负点，或通过实例交互式解码使用 TP mask 提示，再加入对应证据；同时保留仅用 TP 提示的同接口对照。

不应直接继续放大框或仅修改回退阈值，也不能用本轮扩展 Oracle 更高作为上线依据。任何新方案仍需验证其相对原 TP 的真实收益，并与同解码接口的非 PC 对照区分。
