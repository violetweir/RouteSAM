# E0 诊断报告（全部基于现有存档，0 GPU）

生成脚本：`E0_diagnostics_20260914/e0_diagnostics.py`；数值：`e0_results.json`；统一候选表：`per_candidate_*.csv`（Dice 一律由 mask + GT 重算，与存档值逐位一致）。

## 结论速览

1. 样板分数偏置是**真实且量级差异极大**的：偏置比 Kvasir 0.68、ISIC2018 1.10、BUSI 5.42。BUSI 上减掉 `mu_A` 后 85% 的 test 目标改选样板，集中度 0.985→0.348。
2. ISIC2018 的偏置比 1.10 > Kvasir 的 0.68，且改选比例 65% 明显高于 Kvasir 的 43% → **预测 ISIC 的校准收益显著大于 Kvasir**（待 P1 验证）。
3. 原始分数存在大量并列：Kvasir 12%、ISIC 9% 的 test 目标在 raw 最高分上**没有唯一最佳样板**，argmax 是任意的；校准能把并列拆开。
4. 三个数据集的瓶颈不同：Gap(router) Kvasir 0.0462、ISIC 0.0180、BUSI(raw) 0.0503、BUSI(cal) 0.0715。BUSI 校准后天花板大涨但 Gap 反而变大 → 校准之后验证器成为新瓶颈。
5. 免标注的深度选择：只有 `argmax q_cycle` 是**真正的逐目标**规则；它在 ISIC 上胜过最优固定深度（0.8617 vs 0.8566），在 Kvasir 上不如（0.8729 vs 0.8871），在 BUSI 上接近（0.5305 vs 0.5394）。`path_mean` / `path_bottleneck` 随深度单调或有并列，argmax 近似等于『永远取最深』，不是真正的深度选择器（见 E0.6 说明）。

## 这些结果对故事意味着什么

- **可比性条件是真实存在的**，而且可以用一个免标注标量（偏置比）排序三个数据集。
- **校准的收益可以直接预测**：偏置比 BUSI 5.4 > ISIC 1.1 > Kvasir 0.7；BUSI 已实测大涨，ISIC 是**待验证的强预测**。
- **分数只是弱代理**：q_cycle 与 Dice 的秩相关在 0.0~0.5 之间且随深度衰减，BUSI 上甚至为负 —— 这正是 Gap 的来源，也说明"分数高"不能当作"分割好"。
- **三个数据集卡在不同环节**：Kvasir 上限高、验证器一般；ISIC 验证器较准、但样板排序有偏；BUSI 严重偏置，校准后天花板大涨而验证器变成新瓶颈。

## 还需要 GPU 才能补上的（E0 不能替代）

1. **P1 前哨**：ISIC/Kvasir 的"校准 top-1 vs 原始 top-1"在 b0 上的实际 Dice —— E0 只能证明"排序会变"，不能证明"变得更好"。
2. **P2/P3 主实验**：Kvasir 全 bank、ISIC top-5，才能给出与 BUSI 同口径的 Oracle(k) 与 realized。
3. **P4 随机对照**：E0 完全没有下游 Dice 证据表明"贪心选样板优于随机"；历史随机 100 组只比了覆盖代理指标（`coverage_metrics.json` 明确写有 `No propagation performed`）。
